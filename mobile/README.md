# Location Info Explorer — Mobile

Flutter app implementing the node-graph UI from `SDD.md` §6, backed by the
FastAPI service in `../backend`.

## Verified build

Flutter 3.44.8 (stable) was installed in the build environment and used to
scaffold and verify this app for real:

- `flutter create .` generated the platform folders (`android/`, `ios/`,
  `web/`, `linux/`). They're gitignored on purpose (see `.gitignore`) —
  they're boilerplate the SDK regenerates identically for anyone, so run
  `flutter create .` yourself before your first build.
- `flutter pub get`, `flutter analyze` (0 issues), and `flutter test` (widget
  test passes) all ran clean.
- `flutter build linux` and `flutter build web` both compiled successfully.
- The Linux build was actually launched (under Xvfb) against a running
  instance of the backend: the search screen, the node-graph (tier 1 → tier
  2 → detail panel with a working refresh button), and the AI Assistant
  settings screen all rendered correctly and pulled live data from the
  backend's `/api/v1/llm/usage` endpoint.
- `lib/l10n/generated/*.dart` was regenerated by the real `flutter gen-l10n`
  during `pub get`, replacing the hand-written fallback versions that were
  in this file tree before the SDK was available — same API, so nothing
  else needed to change.

What's still unverified: Android/iOS builds (no Android SDK/Xcode in this
environment) and behavior against real upstream APIs (no API keys
configured here — see `backend/.env.example`).

## Setup

```bash
cd mobile
flutter create .          # scaffolds android/ios/web/etc. around lib/
flutter pub get
flutter run
```

## Pointing at the backend

`ApiClient` defaults to `http://10.0.2.2:8000` on Android (the emulator's
alias for the host machine's `localhost`) and `http://localhost:8000`
everywhere else. Override at build/run time if needed:

```bash
flutter run --dart-define=API_BASE_URL=http://192.168.1.50:8000
```

Start the backend first (see `../backend/README.md`) — without it, use the
"Try a demo" button on the search screen, which loads fixture data from
`lib/data/mock_location.dart` matching the backend's JSON schema.

## Structure

- `lib/screens/graph/` — the node-graph (tier 1 groups, tier 2 details, detail panel).
- `lib/screens/settings/` — language/units, AI assistant (LLM), data & privacy.
- `lib/screens/search/`, `lib/screens/history/` — simple functional screens; SDD §10 had no spec for these, so they're deliberately minimal.
- `lib/widgets/node_graph/` — ring layout math, node widgets, connector painter, all animation respecting reduced-motion.
- `lib/theme/` — palette + typography locked in by SDD §9 / CLAUDE.md, do not change without checking with the project owner.
- `lib/services/` — `api_client.dart` (backend calls), `secure_storage.dart` (BYOK key only), `settings_service.dart` / `history_service.dart` (SharedPreferences).
- `lib/state/` — `AppSettings` and `LocationProvider`, both `ChangeNotifier`s wired via `provider`.

## Icon set note

The SDD prototype used `lucide_icons`/`flutter_lucide`. This environment
can't verify exact package versions against pub.dev, so Material Icons are
used instead via a single mapping table (`lib/widgets/node_graph/graph_icons.dart`)
— swap the package in there if you want the closer visual match.
